# UrbanVista — reproducible, paper-inspired PyTorch implementation

**Status:** Complete source-code repository with an operational data-preparation path, full CNN–LSTM + OSM architecture, classification/segmentation training, named ablation variants, baseline models, held-out evaluation, figures and automated tests. **This is a new independent implementation derived from the UrbanVista manuscript; it is not the original authors' recovered code.** The paper's published metrics **are not hard-coded and have not been reproduced**.

## Scientific scope: read before publishing or citing results

The manuscript describes **five urban LAND-USE classes**: residential, commercial, industrial, agricultural and recreational. A ready-to-use public dataset with aligned multi-date Sentinel-2, OSM footprints and independent pixel masks for all five classes was not supplied with the paper. Consequently, the **fully automatic** benchmark in this repository uses real Sentinel-2 (2021), OSM geometry (retrieved at run time) and **ESA WorldCover 2021 land-COVER labels** for five different classes: tree cover, grassland, cropland, built-up and water. **Land cover is not land use. This public benchmark cannot be reported as a reproduction of the five-class manuscript experiment.**

If you possess *independent* 5-class land-use polygons, you can run the same pipeline using `--labels path/to/your_labels.geojson` or `.gpkg`. Labels must be georeferenced polygons with a `class_id` column containing integers 0–4: (0) residential, (1) commercial, (2) industrial, (3) agricultural, (4) recreational. Do **not** reuse OSM land-use polygons as labels while supplying the corresponding land-use tags as model inputs. The implementation **deliberately excludes OSM land-use tags from architectural features** to reduce target leakage. Independent polygon labels still require provenance and leakage auditing by the researcher.

Do not copy the numeric performance values in the manuscript (89.3% accuracy, 0.73 mean IoU, or the previously proposed ablation numbers) into results. They were not generated by this code. Actual outcomes are computed solely from training and held-out data.

## Requirements

- Python 3.10–3.12; PyTorch 2.3+; recommended NVIDIA GPU with >= 16 GB VRAM for the default 128-pixel, four-date, batch-32 experiment. Reduce batch size on smaller GPUs.
- Several GB free for temporary cloud-optical-raster I/O, processed patches and checkpoints.
- Internet access to Microsoft Planetary Computer STAC/COGs, public ESA WorldCover S3, and OpenStreetMap Overpass. No API key required for normal low-volume Planetary Computer use, but external servers can rate-limit or be temporarily unavailable.
- For remote rasters, a GDAL/rasterio installation with network `/vsicurl` support is needed.

Install (Linux/macOS, Windows with a geospatial Python/conda environment):

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[all]'
```

On Windows, activate `.venv\\Scripts\\activate` instead of the `source` command. If your GPU needs a specific CUDA PyTorch build, install PyTorch first using its official selector, then install this package. Installation of geospatial libraries through conda-forge can simplify native dependencies.

## Quick start: complete **real-data** workflow

Run these commands in the repository root:

```bash
# 1. Obtain REAL Sentinel-2, WorldCover labels, and OSM building/road features.
urbanvista prepare --config configs/berlin_worldcover_2021.yaml

# 2. Run the full UrbanVista and four controlled ablations (five seeds each).
urbanvista run --config configs/berlin_worldcover_2021.yaml --models ablations

# 3. Run CNN segmentation and image-transformer baselines.
urbanvista run --config configs/berlin_worldcover_2021.yaml --models unet deeplabv3plus segnet vit swin
```

Each model / seed produces `model.pt`, `test_metrics.json`, `learning_history.json`, `run_config.json`, `environment.json`, `training.png`, `classification_confusion.png` and (when segmentation is available) `segmentation_confusion.png` plus `segmentation_example.png`. The aggregate folder `runs/berlin_worldcover_2021/` contains `results_by_seed.csv` and `aggregate_summary.json` with paired comparisons. Every measured number comes from executed test-set predictions.

**The public dataset download is non-trivial**: server speed, Sentinel product cloud coverage and OSM rate limits vary. The pipeline **fails explicitly** if required data are unavailable or fewer than 30 usable patches remain; it does not substitute synthetic observations. The geographic coverage and quality may be insufficient for robust high-accuracy learning from the small default Berlin area: enlarge the AOI after confirming the smoke tests.

### Independently labeled five-class LAND-USE run

Prepare your independent land-use polygons with a `class_id` integer column (0–4 as defined above). Set `output_dir` and `name` in a copied YAML config to new values so you do not mix data with WorldCover runs. Then run:

```bash
urbanvista prepare --config configs/berlin_worldcover_2021.yaml --labels labels/berlin_landuse_independent.geojson
```

The file path above is an **example of a user-provided independent dataset**, not a bundled download. This command cannot run until the researcher supplies genuine independent land-use labels. The default public dataset path requires no user-provided files. For the actual study's five-class performance claims, the labels, acquisition period, geographic region and split must match those of the original study, if recoverable.

### Dataset output schema

Each `data/processed/.../patches/patch_ROW_COL.npz` contains:

| Array | Shape | Meaning |
|---|---|---|
| `images` | `T,4,H,W` | Sentinel-2 surface reflectance B02/B03/B04/B08, scaled to [0,1], clouds and nodata set to 0 |
| `osm` | `(10,)` | OSM architectural descriptors; no OSM land-use labels |
| `mask` | `H,W` | integer 0–4 per pixel or 255 for undefined; WorldCover or independently supplied labels |
| `label` | scalar | dominant valid class in the patch |

`metadata.json` records sources, dates, classes and region; `records.json` gives patch details, raw descriptive quality counts; `split.json` contains geographically-blocked partition indices; `feature_stats.json` stores training-only normalization statistics.

The 10 architectural descriptors are: mean `sin(2θ)`, mean `cos(2θ)`, axial orientation dispersion, buildings/km², building footprint coverage fraction, mean height in metres, missing/estimated-height fraction, road length km/km², mean building area in m², and log(1+building count). The minimum rotated rectangle's **long axis** provides orientation. UTM line endpoints are inverse-projected and measured using WGS84 geodetic azimuth relative to true north. Near-square polygons have no stable axis and are excluded from orientation averages. When height is missing, no class-informed target imputation is used; missingness is explicitly signaled to the network. Levels multiplied by 3 m are an *approximation*, not measured height.

The 2021 WorldCover label raster and 2021 Sentinel imagery are time-aligned by year. **OpenStreetMap data are the CURRENT snapshot downloaded at execution time**, so there is an unavoidable temporal mismatch; this is saved in metadata and is a validity limitation. The STAC scene cloud percentage filters products; Sentinel's SCL cloud mask filters pixels. All four observations must have adequate coverage. The geographic-block split prevents overlapping patches between train/validation/test but does not eliminate all spatial autocorrelation.

## Model design and evaluation

- **UrbanVista**: shared 4-band CNN spatial encoder; LSTM sequence encoder using CNN pooled embeddings; OSM MLP architectural encoder; vector concatenation; classification head and image segmentation decoder with temporal/architectural FiLM conditioning. Segmentation uses the *last-date* spatial CNN features and conditions them on aggregated temporal/OSM information.
- **Ablations**: `cnn_only`, `cnn_osm`, `cnn_osm_orientation`, `cnn_lstm`, `urbanvista_full`. For controlled orientation ablation, the first three architectural values are zeroed while leaving the rest unchanged.
- **Baselines**: `unet`, `segnet`, `deeplabv3plus` are compact self-contained image-only CNN implementations trained from scratch, **not original/pretrained published implementations**. `vit` and `swin` use unpretrained `timm` architectures as image-only classification baselines, with no segmentation outputs.
- **Classification**: softmax cross-entropy. **Segmentation**: cross-entropy (ignore class 255) + masked multi-class Dice loss. Multi-task loss combines the two. Optimizer Adam, LR 1e-4, 100 maximum epochs, batch size 32, 10 epoch patience, as in the revised manuscript's described hyperparameters; these were **provided in the revised manuscript, not independently verified original training logs**.
- **Metrics**: confusion-matrix aggregated accuracy, macro precision/recall/F1, per-class IoU and mean IoU, pixel accuracy. Results aggregated over five preset seeds 11/22/33/44/55 using arithmetic mean and sample SD. Paired Wilcoxon comparisons are reported when overlapping seed runs exist. **With only five nonzero independent paired differences, the smallest exact two-sided Wilcoxon p-value is 0.0625**, so a claim of significance at p<0.05 cannot be supported with a five-pair exact test. Increase the number of genuinely independent runs if warranted; do not fabricate p-values.
- **Augmentation**: horizontal/vertical flip + small spectral brightness perturbation. Random 90° rotations were *not* implemented; horizontal/vertical reflections update the axial sin(2θ) component consistently to preserve geographic orientation meaning. This avoids an otherwise subtle data-feature mismatch.

No regression target is provided; the code intentionally does not report MSE, RMSE, or R². Unpretrained transformer baselines are **classification-only**, so `mean_iou` is null.

## Verification without downloads

```bash
pytest -q
urbanvista smoke-test
```

The smoke command creates **explicitly synthetic** fixtures to exercise the real training loop, saves nothing unless `--workdir` is given, then deletes its temporary folder. It **must not be cited as an experimental benchmark**.

## Integrity policy and known differences from the manuscript

1. This repository **does not establish that the original paper's claimed experiments were executed** and cannot certify its reported tables or schematic figures.
2. The paper has not supplied original spatial location, image dates, class label provenance, splits, layer hyperparameters, trained weights, or logs. We document our explicit implementation choices instead.
3. The automatic public benchmark uses the five WorldCover land-cover classes, whereas the manuscript's five classes are urban land-use categories. They must not be conflated.
4. Most publicly downloadable remote-sensing datasets do not provide matching building footprint coordinates. This project therefore acquires its own georeferenced inputs rather than incorrectly assigning OSM metadata to unrelated EuroSAT imagery.
5. OSM building heights are incomplete; the coverage/quality counts in saved metadata permit auditing, but sensitivity experiments require actual retraining.
6. The illustrative figures generated elsewhere in manuscript preparation are **not** evidence for this repository; only `segmentation_example.png` generated on held-out labelled image patches can be described as an experimental output.
7. If publishing this as a scientific reproduction, cite new experiments with their actual data, configurations, provenance, code commit and metrics, not values inserted earlier in manuscript drafting.

## Prediction with a trained checkpoint

After `urbanvista run`, select any `.npz` from the **same prepared dataset** and use a saved checkpoint, e.g.:

```bash
urbanvista predict \
  --checkpoint runs/berlin_worldcover_2021/urbanvista_full/seed_11/model.pt \
  --patch data/processed/berlin_worldcover_2021/patches/patch_0000_0000.npz \
  --dataset-root data/processed/berlin_worldcover_2021 \
  --output predictions/example
```

The above sample filename may differ if that geographic patch was filtered out for clouds; choose any actual `.npz` in the patches folder. Outputs are `prediction.json` with class probabilities and, when available, `segmentation_class_ids.png` containing class indices. If the patch contains saved map-location metadata, the tool also creates a georeferenced segmentation GeoTIFF. Input normalization uses **the saved training-set statistics**. This command will not interpret arbitrary unreferenced satellite screenshots or supply invented OSM features.
